## 审阅修复

1. 移除本次新增的历史记录累计 500 条硬限制，避免普通收件和查询永久阻塞。完整历史有界保留和清理尚未在本轮实现。
2. 用户明确检查后，先清输入阶段恢复屏障，再解除异常暂停；存在旧剪贴板恢复记录时保持暂停，不静默丢弃。
3. 永久非法文字标记为 Rejected，保留记录并允许补写处理下一条，避免非法队首一直阻塞。
4. 会话失效独立于回执是否已被过期清理，停止收发、暂停输入并删除上下文；收件侧失效走相同处理。

## 实际运行验收

- 已核对旧实例路径，备份加密状态后换用新版本；原绑定成功恢复，无需重新扫码。
- 正常用户桌面启动通过授权环境完成；不使用程序主动切换 Windows 桌面的机制。
- 首次用户反馈未收到查询回复，增补脱敏轮询阶段、完成次数和错误类型指标。之后实际收到一条新文字并成功调用发送接口，用户明确确认手机看见“已派发，尚未确认写入结果”回执。
- 首次成功发送的实际消息未匹配 `/状态`，未将它作为查询通过的证据。随后用户针对“关闭自动输入、发送 `/状态`”的验收问题明确反馈“两种回复都收到了”，据此记录暂停通知和状态查询的手机可见性已确认；不是根据本地发送计数推定。
- 实测前后 Dispatched 从 1 增至 2、待发回执归零；没有把该次输入称为 Verified。

诊断不包含正文、身份标识、上下文或凭据；“API 发送成功”计数也不代表用户已读。

反馈后只读检查：连接状态为 connected，待发回执为 0，未记录错误类型；自动输入和自动回车均为开启。该快照反映检查时状态，不用于重建此前暂停和查询的全部时序。

## 保留限制

不实现 Codex / Antigravity 手机切换或其任务监测，切换仅保留事件接口；通用输入执行器既有的焦点判断及 Enter 风险仍存在。当前应用和输入框状态无法确认时如实回复“未确认”。回执有效期 5 分钟为本地策略，不代表微信服务端保证；超时后复用 client_id 仍不承诺端到端恰好一次。本文不表示整个 P0 的跨应用、100 条文字、30 条语音或长期断网验收已经完成。

# 微信连接器状态回执设计

日期：2026-11-07。状态：用户已授权并已实现，112 项离线测试通过；用户已确认手机收到输入结果回执、暂停通知及 `/状态` 查询回复，本轮基础回执验收完成。

## 目标与已确认范围

用户要求把连接器状态作为普通文字回复到原微信 ClawBot 私聊。用户选择首版仅包含应用切换、输入成功/失败、暂停等连接器状态；不包含 Codex / Antigravity 的任务运行、完成和报错监测。

保留无需绑定目标应用的使用方式。应用切换与各应用适配器是此前正在分析的独立能力；本改动提供其状态回执接入口，不把未实现的切换功能报告成已完成，也不在本改动中实现应用适配器。

## 现有代码与改动必要性

- `Connector.WeChat/ILinkClient.cs` 目前仅登录、收件和生命周期通知，没有 `sendmessage` 客户端。
- `MessageParser.cs` 校验绑定身份并提取文字，但没有保留入站 `context_token`。缺少转写的消息也需要关联原会话回报原因，回复上下文不能仅挂在非空 TextEvent 上。
- `NativeProbeResult` 已区分 Queued、Dispatched、Verified、Uncertain；当前 PillWindow 把 Dispatched 和 Verified 都显示为已打入，且没有完整持久化输入结果。微信回执必须从真实结果产生，不能复制这段显示判断。
- 本阶段沿用现有 DPAPI 原子状态文件，不为回执引入服务器、SQLite、AI 服务或新运行时依赖。

## 回执内容与触发规则

以下为本次实施采用的默认文案和频率：

- 应用切换并确认可编辑焦点：`已切换到 Antigravity，输入框已就绪。` 只有适配器真实确认后才能发送。
- 仅窗口切换成功但找不到输入框：`已切换到 Antigravity，尚未找到输入框；后续文字暂存。` 不得称为输入就绪。
- 切换失败：`未能切换到 Codex；后续文字暂存。` 不得退回旧窗口继续输入。
- Verified：`已确认写入 Antigravity，共 28 字。` 目标应用不可识别时使用“当前输入框”；字数使用 Unicode 文本元素计数。
- Dispatched：`已派发到当前输入框，尚未确认写入结果。` 不得使用“成功”“已输入”，不得自动重放该条。此回执本身不改变自动输入开关；结果不明的 Uncertain 才强制暂停。当前直接输入路径通常返回 Dispatched，不能为了新增回执把每条普通输入都变成需要人工恢复。
- Queued：`未执行输入：没有可用输入框。内容已暂存。` 拒绝原因采用固定中文映射，不回传异常堆栈或任意错误正文。
- Uncertain：`输入结果不明，自动输入已暂停；请检查电脑后再处理本条。` 禁止自动重放。
- NeedsTranscript：`本条语音未收到转写文字，未执行输入。`
- 暂停/恢复：`自动输入已暂停。` / `自动输入已恢复；历史积压不会自动补写。` 仅实际状态发生变化才通知。
- `/状态`：作为保留的完整文字指令处理，不写入电脑；返回连接状态、当前已确认应用/输入就绪状态、自动输入开关、自动回车开关、待处理数量。无法确定的字段写“未确认”。第一版不识别自然语言查询指令。

每条入站消息正常仅发送一条最终处理回执，不逐阶段发送“收到/处理中/派发中”。状态查询与实际暂停/恢复是单独的状态事件。暂停期间收到文字，仍回报“自动输入已暂停，内容已暂存”。

不回显输入正文、文档/会话标题、文件路径、Token、context_token、消息原始 JSON。每条输入回执可带 8 位摘要编号供用户对应消息，内部仍以完整消息 ID 去重。回执正文上限 500 个 Unicode 文本元素。

## 协议与身份边界

参考腾讯固定基线提交 `874637a0dbc24050f72d1385add4fc6170a2d726` 的文本发送契约：`POST /ilink/bot/sendmessage`，携带 `base_info` 和已校验的 HTTPS 微信域名鉴权；关闭 HTTP 自动重定向。

出站 msg 使用 `message_type=2`、`message_state=2`、文本 item、稳定 client_id、绑定 OwnerId 作为唯一接收者，以及对应已认证入站会话的 context_token。业务返回码和 HTTP 状态均检查，不打印服务端原始响应。

新增独立 ReplyContext（账号、所有者、会话上下文、来源消息 ID、收到时间），由身份校验通过的消息产生，供 Queued、NeedsTranscript、查询和控制结果共同使用。它保存在 DPAPI 密文内，不进诊断文件。

没有上下文时不猜测、不拿其他账号/会话的上下文代用；本地显示回执不可发送，等待用户发送新消息或 `/状态`。缺少上下文的可用性必须实测，首版不假设腾讯允许无上下文发送。

只回复绑定用户；未授权消息、群消息、Bot 自身消息不触发回执。收到出站消息副本时直接忽略，不能回执自己的回执，不能进入输入队列。

## 状态持久化与发送可靠性

输入与回复分为两条串行流程。输入结果及待发送回执在同一次 DPAPI 状态文件保存中落盘；回复失败绝不再次执行输入。所有状态修改通过同一协调器串行合并，避免异步收件和发件覆盖彼此的状态。

沿用现有 ProbeState 并增加可选回执队列及上下文属性，保持旧文件反序列化兼容。开始输入前先保存 Inserting；完成后保存实际结果与回执。重启遗留 Inserting 转 Uncertain 并暂停，不能仅凭回执未发送推断输入未执行。

回执去重键为“绑定账号 + 来源消息 ID/本地状态事件 ID + 状态版本”，重试复用相同 client_id。服务端未提供已核实的端到端幂等承诺，因此不承诺微信恰好显示一次。

建议默认上限：每秒最多 1 次发送请求，待发回执最多 100 条，其中普通回执最多 99 条，另保留 1 条 `/状态` 查询回复位置。从回执产生起最多尝试 5 分钟，网络失败依次间隔 2、5、15 秒，最多重试 3 次。此 5 分钟是本地策略，不代表服务端上下文有效期承诺。超时/断网可能出现未知发送结果，复用 client_id，避免无界重试。

普通回执达到 99 条时先暂停新的电脑输入、保留入站文字，显示“回执队列已满”。拥塞期间不再逐条生成“已暂停”回执，而是增加未生成回执计数；这是逐条回报规则的容量例外，不以发送成功处理。`/状态` 优先发送，返回拥塞和省略回执数量；如果已有未开始发送的查询回复，则替换为最新查询及其上下文，被替换项计入省略计数，不能挤占正在发送的项。恢复发送后保持输入暂停，待用户明确恢复。过期回执删除敏感上下文并记本地丢弃计数；重新联网不集中补发过期成功消息，用户可用 `/状态` 查询当前情况。

会话失效立即停止发送与接收，不反复尝试旧凭据。电脑断网、关机或进程退出时无法即时发送离线通知；不能将未发送的提示称为“已通知微信”。启动登录成功但尚无有效入站上下文时，也不主动发送上线回执。

本地按钮暂停/恢复使用同账号最近一次已认证会话上下文；距离该入站消息超过 5 分钟时只在本地显示状态，等待下一次入站消息建立新上下文。回执到期策略同样约束此路径。

## 实现边界与验证

实施时修改 Core 的上下文/回执模型、WeChat 的解析与发送客户端、Probe 的输入结果协调与回执发件流程，新增独立 formatter/sender/coordinator 文件，避免继续把逻辑堆入 PillWindow。保留当前普通输入行为；本改动只增加完整匹配的 `/状态` 保留指令。

测试必须覆盖：发送请求与 context_token 精确关联、绑定身份拒绝、Bot 回执不循环、NeedsTranscript 可回复、无上下文不发送、Dispatched 不冒充 Verified 或改变输入开关、结果不明暂停、重启不重复输入、收件/发件并发不丢状态、失败仅重试回执、过期/容量/节流限制、99 条普通回执后继续收件不突破 100 条及查询保留位、查询替换不覆盖正在发送项、敏感信息不进入回执与日志、旧状态文件兼容、`/状态` 不写入电脑。

先跑失败测试再实现；全套测试和 Release 构建通过后，在用户已授权的绑定私聊内发送明确标记的状态测试消息，实测普通输入成功/暂存/结果未确认和暂停回执。切换状态仅用适配器事件契约测试，待真实应用适配器实现后另行实测，不能据此宣称手机切换已经完成。

当前输入执行器本身的焦点宽松、换行转 Enter 等已知问题不因增加回执而被视为已解决；本功能也不能将输入确认等同于目标应用已提交或 AI 任务完成。

## 决策归属

用户已确认：回微信文本，首版仅连接器状态。

采用方案：一条消息一条结果回执、上述文案、`/状态` 指令、5 分钟截止、容量与重试限制、不回显正文、保持既有执行方式在当前会话内逐项实现。用户已于 2026-11-07 要求考虑架构后开始执行。

独立 builder check 已完成：唯一重要未决点为回执队列拥塞时如何处理新回执；已由作者补充 99 条普通回执加 1 条优先查询保留位、拥塞计数及查询替换规则，无需用户追加需求。

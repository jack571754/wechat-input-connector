# 桌面交互升级设计

状态：设计提案，待用户确认；不代表已实现。2026-11-08。

独立 builder check 已完成，结论为“没有重要未决问题”。源码检查与设计示意均已完成；示意不是运行界面截图，尚未做真实窗口视觉验收。

## 目的与边界

让连接器常驻时安静、操作时明确。用户已要求默认绿色、无需选择绑定应用、取消输入结果回读和结果不明自动暂停；历史仅在电脑端，以简单列表和正文查看连接器收到的微信消息及输入记录。沿用 WPF，不更换技术栈、不新增微信历史命令、不读取 Codex 或 Antigravity 的聊天记录。

本设计中的尺寸、配色、布局和快捷键为设计建议，尚未得到用户确认。切应用及手机编号菜单仍属于另一份待实施设计，不在本次界面中展示为可用能力。本轮交互优化也不代表此前实际输入未出现文字的问题已解决。

## 现状依据

- PillWindow 的状态文字和补写按钮都调用 TriggerManualReplayAsync；用户可能把查看状态误操作成输入。InsertNextAsync 实际处理最早待输入条目，当前“最新文字”的提示不准确。
- 点击和拖动共享 MouseLeftButtonDown/Up，缺少拖拽阈值；右键直接打开设置，缺少可发现的历史入口。
- ReportSessionStatus 每次展开悬浮窗；设置窗口始终置顶、隐藏于任务栏，整窗可拖动；普通切换控件只响应鼠标。
- 托盘重复提供设置开关，并残留“已检查输入结果，解除暂停”的入口；与用户已要求的行为不一致。
- 以上为源码检查结论，尚未完成当前窗口的视觉及真实焦点复现。

## 信息结构与操作

### 悬浮点与状态条

- 48×48 DIP 的绿色悬浮点为常驻入口，移除发光效果；鼠标悬停显示“微信输入连接器”，不自动展开。单击只展开状态条，达到系统拖拽阈值后只移动，不再触发单击。
- 展开条宽约 320 DIP、高 48 DIP，左侧绿色标记与短状态，右侧“历史记录”和更多菜单。状态文字不再触发补写。条内不出现退出、重新扫码等管理操作。
- 日常来消息仅更新短状态，不展开、不闪烁、不抢焦点、不显示消息正文。状态条鼠标离开 3 秒后收起；菜单展开或用户操作时不收起。
- 悬浮点、状态条、托盘查看状态不激活窗口，不改变外部应用的输入焦点。展开收起固定同一屏幕锚点；位置保存到本机设置，显示器移除或 DPI 改变后约束到可用工作区。
- 右键和更多按钮使用同一菜单：历史记录、设置、隐藏悬浮窗、退出。托盘双击打开桌面窗口，右键同一菜单；隐藏悬浮窗后可由托盘恢复。

### 桌面窗口

- 一个可调整大小、能通过任务栏和 Alt+Tab 找到的普通窗口，初始 860×560 DIP、最小 680×420 DIP；不强制置顶。顶部两个页签“历史记录 / 设置”，避免多个管理窗口相互遮挡。扫码绑定也放在设置页的连接区域。
- 标准标题栏支持移动、最小化和关闭。关闭只关闭此管理窗口，连接器继续运行；明确的“退出连接器”位于更多菜单内。重复打开激活已有窗口，保留所选记录及滚动位置。
- 历史页左侧约 300 DIP 的简单列表，按收到顺序由新到旧，显示本机时间、单行摘要、文字状态。右侧显示所选记录的完整纯文本、接收时间、状态和只读说明。默认选中最新一条；有新消息时列表更新但不改变用户当前选择和正文阅读位置。
- 第一版不增加搜索、筛选、统计、分页按钮、导出、删除或逐条重发。数据量大时采用虚拟化列表，正文按选中条目读取；不截断存储的正文、不把全文塞进列表。
- 正文可选择和复制，显示“复制正文”按钮；仅用户点击时写剪贴板，不自动恢复剪贴板。复制反馈使用按钮原位文案，不发微信通知。
- 空记录显示“还没有收到消息”；收到无转写语音显示“未收到语音转写文字”，不推测内容。只展示当前绑定身份的消息，排除身份拒绝诊断项和控制查询，原始错误、context_token 等不进入视图。身份切换必须清除旧选择与正文。
- 直接使用现有 DPAPI 保存的事件；在线读取协调器的只读快照，未连接时读取已加载的当前身份事件，不另建明文数据库。无法加载时显示本地读取错误及重试入口，不自动重新绑定、不展示上个账号的缓存。

### 设置页

- 连接：当前连接状态和绑定信息；已连接时将“重新扫码”收进更多操作，点击后确认将重新绑定；连接失效时显示直接可见的“重新连接”。正常短暂断网继续复用现有自动重连，不要求扫码。
- 输入：保留“自动输入”和“输入后回车”两个原有设置，说明分别为“新消息写入当前输入框”“输入后追加 Enter”；说明回车的实际作用，不把它描述为所有应用都能发送。不会新增“暂停”按钮或自动暂停逻辑。
- 显示：保留“悬浮窗置顶”；只影响悬浮点及状态条，不影响管理窗口。
- 删除过时的结果确认/解除异常暂停入口。设置使用原生可键盘操作的开关，不再自绘仅鼠标可操作的 UserControl；托盘不再重复设置开关。
- Ctrl+Alt+V 保留为“补写下一条待输入消息”，只在用户将焦点放回外部输入框后主动使用，调用现有队列规则；无可补写记录时如实提示。不在历史正文上放置输入或重发按钮。

## 焦点和状态约定

- 桌面窗口为正常可激活窗口，查看和复制时允许获得焦点。此时收到新消息继续保存和回复；输入执行器必须识别本进程所有窗口并拒绝向自身输入，条目标为待输入、理由“正在查看连接器”。不设置全局暂停、不自动激活历史目标、不自动补写积压。
- 关闭管理窗口不主动切换任何其他应用；后续新消息仍按用户当前外部输入框处理。若当前没有合格输入框，继续现有拒绝/待输入规则，不能降级投到历史窗口或旧窗口。
- 绿色表示连接器常态标识；“微信已连接 / 正在重连 / 需要重新连接 / 自动输入已关闭”等文字独立表达实际状态。真实断线或终止沿用灰色指示，不把离线标为在线。取消普通黄色警告与确认动画。
- 历史状态准确表达“已派发 / 待输入 / 派发中 / 结果不明 / 缺少语音转写 / 已过期 / 已跳过”；旧 Verified 标记为“历史已确认”。不新增写入后回读，不把派发记录写成“输入成功”。
- 后台普通状态变化不弹窗；需要扫码或持续故障时在条内给出可操作入口，用户打开窗口后查看原因。状态说明与窗口展示均为只读，不改变 AutoInput 和 AutoEnter。

## 视觉建议

中性浅灰桌面窗口，绿色只用于品牌点、选中标记和主要连接动作。背景 #F5F6F7、内容 #FFFFFF、主文字 #202428、次文字 #667078、分隔线 #E3E7E9、品牌绿 #07C160。悬浮点沿用绿色；状态条白色不透明底，正文窗口使用系统字体 Microsoft YaHei UI / Segoe UI，正文 14 DIP、辅助 12 DIP、页标题 18 DIP，行高约 1.5。

8 DIP 间距体系，普通按钮高度至少 32 DIP，输入/点击区域至少 36 DIP；窗口采用原生边框与系统阴影，不再叠加透明发光和多层自绘阴影。仅展开和页签切换可用不超过 120ms 的轻量反馈，尊重系统减少动画与高对比度设置。正文可换行、滚动，长消息不会撑开窗口；图标用统一线性几何或系统符号，禁用 emoji 混搭。示意图中的内容均为虚构设计样例，不是用户的实际记录。

## 实施分段与验收

1. 提取当前身份的只读历史视图模型，补充身份过滤、状态映射、无转写、空列表和长正文测试；新增单一管理窗口及历史/设置两页，复用现有加密存储与设置操作。
2. 精简 PillWindow 和 TrayManager 的入口，删除状态点击补写及过时暂停入口；补充本进程前台拒绝规则与非激活悬浮窗，核对队列不重放、正常新消息继续输入。
3. 全套测试及 Release 构建后独立发布；备份加密状态，再替换本机版本。手工验证单击/拖动、键盘操作、多显示器与 100%/150% DPI、长正文阅读不跳动、关窗继续运行。
4. 重点实测：外部输入框留光标后展开状态条，焦点仍在外部；打开历史页后手机发消息不进入连接器正文，关闭历史后新的消息仍按当前焦点处理；复制正文不触发输入；任何派发成功文案不得冒充实际写入验证。

产品代码、发布替换和远程推送均未在本设计阶段执行。设计确认后再生成可逐项验证的实施计划。

# 手机切换 Codex / Antigravity 设计

日期：2026-11-07；2026-11-08 更新为微信编号菜单交互。状态：设计与实施计划待用户确认，未修改产品代码。

初版及 2026-11-08 编号菜单增量均已完成独立 builder check，结论为“没有重要未决问题”。实现细节由实施者在下述边界内决定。

## 用户目标与已确认行为

手机微信发出切换指令后，将目标应用带到前台并定位其消息编辑器，后续新消息持续投到该应用；每次输入前重新确认目标及恢复焦点。用户已明确选择持续投到选定应用，直到再次切换或发送“跟随光标”。原先无需绑定应用的模式继续作为默认及可随时返回的模式。

首版只适配 Codex 桌面版、Antigravity 独立桌面版当前显示的聊天编辑器。应用内切项目、切会话、新建会话、启动尚未运行的应用、AI 任务状态监测均不包含在本次功能中。

## 已核对的架构与本机证据

- Core 的 ReceiptCoordinator 已统一保存输入结果和待发回执，ReceiptSession 装配微信协议、原生输入及独立发件循环；复用该状态保存和回执机制。
- 目前没有切换命令或应用适配器，ReportSwitch 只有回执接入口；/状态 的当前应用及输入框仍固定显示未确认。
- 原生直接输入使用当前焦点且检查过宽；其“只要有 AutomationElement 即属于前台”的判断及 VerifyFocus 吞掉控件变化拒绝，不能用于锁定应用的保证。本次收紧归属与控件稳定检查，覆盖回归。
- 本机 Codex 包身份为 OpenAI.Codex，版本 26.1013.40934，桌面主程序实际名为 ChatGPT.exe；codex.exe 为 CLI，不作为桌面切换目标。身份以包/可信安装路径及窗口进程共同识别，不能仅按窗口标题或进程名匹配。
- 本机 Antigravity 为 2.29.0，位于用户安装目录。只读可访问性检查显示消息编辑器为可设置字符串的“组合框：消息输入框”，不能只查 Edit。
- Codex 安装包资源确认消息编辑器使用 data-codex-composer 及 textbox 语义，但 DOM 标记不能直接当 UIA AutomationId 使用。其 UIA 选择器须在适配验证步骤确认；未确认前只能回报窗口已激活、输入框未就绪。

## 命令契约（作者建议的首版默认值）

- `/应用` 或完整一句“切换应用”：在原绑定微信私聊返回已适配应用的编号菜单，不改变当前窗口或输入目标。编号来自适配器目录，不扫描并承诺支持全部已安装程序。
- `/code` 或完整一句“切换到code”“切换到Codex”：选择 Codex。
- `/anti` 或完整一句“切换到anti”“切换到Antigravity”：选择 Antigravity。
- `/跟随` 或完整一句“跟随光标”：返回跟随当前焦点，不主动激活其他窗口。
- 继续保留 `/状态`；新增 `/输入 ` 前缀，后面的内容按普通文字处理，允许输入与保留命令同名的文字。

命令仅在整条消息匹配时触发，首尾空白可忽略，拉丁字母不区分大小写；不做正文关键词搜索、不调用模型猜意图、不执行手机传来的脚本、路径或任意程序名。切换指令不写入任何编辑器。未知斜杠指令保留并回报“未识别的连接器指令”，不得意外打到目标应用；普通非命令文字保持原行为。语音只有现成转写完整匹配时才能作为命令。

切换指令只执行首次收到且处于现有自动时间窗内的消息（过去最多 15 秒、未来最多 5 秒）；重复、断网延迟、重启遗留的指令不重新抢焦点，回报过期或已处理。手动补写跳过所有控制指令。

## 微信编号菜单（2026-11-08 用户新增要求）

用户要求连接器通过微信文本列出已添加应用并排号，回复序号切换。建议首版回复格式如下，运行状态和当前目标由真实状态填充，未确认时写“未确认”：

```text
请选择要切换的应用：
1. Codex 桌面版
2. Antigravity（anti）
0. 跟随当前光标

当前目标：跟随当前光标
2 分钟内回复序号；回复“取消”退出。
```

- 编号 1、2 固定，不因应用退出或排序改变；后续新增适配器追加编号，不重排旧编号。未运行或未验证就绪的应用如实标注，不能因为出现在菜单就称已兼容或已就绪。
- 只有已认证绑定私聊主动请求菜单后，下一条整条匹配的 `0`、`1`、`2` 才解释为选择；首尾空白可忽略，不将“第 1 个”“版本 1.2”或正文数字当指令。无菜单时单独数字仍按原普通文字规则处理，`/输入 1` 始终输入数字。
- 菜单从生成起有效 2 分钟，号码映射和菜单 ID 冻结在本次菜单快照中，选择时不能重新按当前应用列表排序。选择、取消、显式其他控制命令或一条普通正文后关闭菜单；普通正文关闭菜单后继续正常输入。
- 已过期、重启取消或回执未能送达的菜单保留一次拒绝旧选择的标记；下一条序号提示“菜单已失效，请发送‘切换应用’重新选择”，不写进输入框，再关闭该标记。重启不保留可执行菜单。
- 有效菜单内的无效纯数字只回复“序号无效，请回复 0、1 或 2”，不写入电脑、不切应用，菜单在原截止时间内继续有效。纯数字最多按 3 位识别为菜单候选，超过 3 位的纯数字也拒绝且不注入，避免绕过菜单保护。
- 选择序号只消费一次：保存解析出的目标后复用原切换路径，保留指令新鲜度、去重、处理中持久化、失败不回旧窗口及实际切换回执。同批“切换应用 → 1 → A”也必须按顺序解析和投递，不能预先将 1/A 当作普通文字投到旧目标。
- 菜单与 /状态 共用现有优先查询保留位，不能突破 99+1 上限；新菜单替换旧菜单并取消旧选择。菜单回执若被替换、过期或最终发送失败，对应菜单失效；同一菜单回执重试不产生新菜单或切换操作。
- 菜单快照与入站命令使用现有 DPAPI 状态保存，身份和会话严格绑定，不输出标题、路径、正文或凭据。菜单过期检查不依赖常驻高频计时器。

## 组件与状态边界

1. Core 增加纯命令解析、输入路由及切换状态。当前模式、选定应用、切换阶段及每条待输入消息的目标随 DPAPI 状态保存；窗口句柄、PID、UIA 引用只在进程内存中保存，禁止跨重启复用。
2. 同一输入操作门闩串行处理切换、自动输入和手动补写；与收发回执共用同一状态协调器。收件先持久化去重，再按服务端数组顺序逐条处理命令、查询和正文；同一批“切 anti → A → 切 code → B”不得先完成全部切换后再输入正文。查询反映排在它之前的操作结果。
3. 每条正文保存当时的目标模式。历史积压不因后来切换而悄悄改投其他应用；切换、解除暂停和重新联网不自动补写积压。手动补写按条目已保存的目标处理，旧版无路由条目按原跟随焦点规则处理。
4. Windows 增加两个独立的 IApplicationAdapter，共用可信窗口枚举、激活、输入框验证。适配器负责找当前聊天编辑器，执行器负责在已验证目标约束下派发文字；不能在最后一步退回“任意当前焦点”。
5. ReceiptSession 只装配适配器与路由，不承担应用选择器细节；PillWindow 仅显示模式、状态和生命周期。发件循环不接触窗口，也不触发重试输入。

## 窗口、输入焦点与失败处理

- 单一目标窗口直接使用；多个窗口时优先同一模式下已成功选择且仍存活的窗口，其次目标应用当前前台窗口；仍不唯一就失败回执，不随意选第一个。首版不切换应用内会话。
- 应用必须已经运行。可恢复最小化窗口并请求前台激活；Windows 拒绝前台激活时如实失败，不模拟 Alt+Tab、不改系统设置、不点击固定坐标。
- 只在已验证窗口内查找适配器白名单编辑器。使用 UIA SetFocus 并检查实际焦点、完整祖先归属、可编辑性、可用性、非密码、无选区、权限、输入法及修饰键状态。目标关闭、模态框遮挡、编辑器不唯一或查找超时均暂存文字。
- UIA 探测置于有生命周期约束的 helper 中，单次总操作最多 5 秒；超时终止本项目 helper 并回报未就绪，防止第三方 UIA 卡住轮询和暂停操作。不得主动切换 Windows 桌面。
- 输入前再次核对目标窗口及同一编辑器；派发后发生变化则 Uncertain，沿用现有人工检查后恢复流程，禁止重放该条。
- 切换失败保留新选定目标、标记未就绪，后续正文只能重试定位该目标或暂存，禁止回落到旧应用。目标未就绪与结果不明暂停分开；重新定位成功不能解除异常暂停，也不能打开用户已关闭的自动输入。
- 自动输入关闭时仍可执行明确切换指令，但不会输入正文。继承现有自动回车开关；本次切换命令及窗口恢复绝不产生 Enter，适配器内文本换行和追加提交键必须分开处理，禁止把多行正文逐行提交。无法可靠支持多行的适配器先拒绝并暂存，不能冒险输入。
- 持续定向会按新消息激活目标窗口；仅切换/新消息时定位，不做后台高频焦点争抢。首次切换只定位编辑器，不移动光标到末尾、不清空或覆盖已有草稿。

## 持久化、重启与微信回执

开始切换先保存目标意图及处理中状态，再调用 Windows；成功或失败后保存实际结果与一条回执。保存失败不能先切窗口。重启保留选定应用但清除就绪确认，未完成切换指令不自动执行；下一条新正文可重新定位该应用。输入结果不明仍保持暂停。

切换结果沿用已定的三种文案：窗口和编辑器均确认才说“已切换…输入框已就绪”；仅激活窗口则说“尚未找到输入框”；激活失败则说“未能切换”。输入回执带实际目标应用。/状态 显示当前路由、选定应用、最近焦点检查时间及是否已确认；历史检查必须标为“最近确认”，不能称为持续实时就绪。跟随模式不声称已锁定某应用。

回执沿用 99+1 容量、节流、有限重试、有效上下文和隐私规则，不包含标题、消息正文、进程路径或凭据；回执发送失败不再次执行切换或输入。旧状态文件保持兼容。

## 验证与交付

TDD 覆盖命令完整匹配及转义、身份与新鲜度、重复不切换、批次顺序、旧积压目标不变、多个窗口、窗口激活失败、唯一编辑器选择、跨进程托管控件的真实祖先归属、控件变化必须拒绝、探测超时、切换失败不回旧窗口、暂停不被定位成功解除、重启不恢复就绪或重执行控制指令、查询和回执语义。

两个应用分别验证：先聚焦其他窗口，再手机切换、焦点丢失后发新消息、最小化恢复、未运行及多窗口失败、已有草稿不被覆盖；初始实测关闭自动回车，确认输入位置后再单测追加提交键。成功以实际目标窗口和文字可见为准，不以 SendInput 返回值替代。Codex 如无法由工具直接检查，采用用户实际操作反馈，清楚记录未验证边界。

保留当前版本与 DPAPI 备份，新版本独立发行；完成一次整体独立审阅、全套测试及 Release 构建后再替换本机运行。用户尚未授权本轮推送远程，不自动推送。
